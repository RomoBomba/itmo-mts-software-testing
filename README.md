# Домашнее задание №3 — Docker и CI/CD для API-автотестов

За основу взят существующий API-тест `PostsTest` из [домашней работы №2](https://github.com/RomoBomba/itmo-mts-software-testing/tree/api-testing-homework).
Он обращается к общедоступному API https://playground.nileslabs.com/api/v1:
создаёт пост через POST, изменяет заголовок через PATCH и проверяет
сохранённые данные через GET.

## Требования для Docker

- Установленный и запущенный Docker Desktop или другая совместимая среда Docker.
- Доступ к интернету для загрузки базового образа, Maven-зависимостей
  и обращения к API.

Java 21 и Maven входят в образ. Для контейнерного запуска устанавливать
их на компьютер отдельно не требуется.

## Проверка теста без Docker

Для этого варианта нужны локальные JDK 21 и Maven 3.9 или новее.
Из корня проекта, где находится `pom.xml`:

```bash
mvn -B test -Dtest=PostsTest
```

## Сборка и запуск контейнера

Обе команды выполняются из корня проекта, где находятся `Dockerfile` и `pom.xml`:

```bash
docker build -t api-test .
docker run --rm api-test
```

При сборке Docker загружает образ с Maven 3.9.11 и Java 21,
подготавливает зависимости и копирует исходники тестов.
Файл `.dockerignore` исключает из контекста сборки Git, настройки IDE
и локальные результаты предыдущих запусков.

Команда запуска теста задана в `Dockerfile` через `CMD`, поэтому после
`docker run` тест выполняется автоматически. В консоли отображаются
результат теста и итог Maven. После завершения контейнер удаляется
благодаря `--rm`.

Успешное выполнение возвращает код `0`. При ошибке запроса или падении
проверки Maven и контейнер завершаются с ненулевым кодом.
В терминале macOS или Linux код можно проверить сразу после запуска:

```bash
docker run --rm api-test
echo $?
```

Локально проверены оба результата: исходный `PostsTest` проходит
с кодом `0`; в отдельной временной копии ожидаемый статус создания
поста заменён с `201` на `200`, после чего тест падает, а контейнер
возвращает код `1`. В рабочем проекте сохранена правильная проверка `201`.

## GitHub Actions

Конфигурация находится в `.github/workflows/ci.yml`.
Workflow `API tests in Docker` запускается при каждом `push` в любую ветку,
содержащую этот файл.

В одной job на `ubuntu-latest` выполняются три шага:

1. Получение исходного кода текущего коммита.
2. Сборка образа командой `docker build -t api-test .`.
3. Запуск этого же образа командой `docker run --rm api-test`.

При ошибке сборки или падении API-теста job и workflow завершаются неуспешно.
Каждый запуск собирает образ из исходников репозитория и не требует
заранее подготовленного локального образа.

[Запуски workflow для ветки docker-ci-homework](https://github.com/RomoBomba/itmo-mts-software-testing/actions/workflows/ci.yml?query=branch%3Adocker-ci-homework).
